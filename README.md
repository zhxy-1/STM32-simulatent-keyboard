# STM32-simulatent-keyboard
The project which is aim at making the STM32 Minium Systemal board as a USB HID Device.

# 设备成果概述：
1.一根标准CtoA的数据线，插Type-C线入STM32最小系统板的STM32接口，另一端插入到电脑上，板子上的PC13开始闪烁，然后短接PB9和相邻的5v引脚，就可以开始输出第一个任务，注意，当在中文模式下输出这个生成是有问题的，要提前切换输入为英文
2.执行完第一个输出之后，蓝色的PC13板载灯开始闪烁，按照刚开始一样的就可以开始输出第二个任务，最后结束的时候会快速闪烁PC13蓝色灯来提示


# 项目思路总体概述：
1.通过STM32CubeMX软件进行开荒和项目初始化生成
2.通过编码程序来对源程序进行转写
3.转写的并不是目标输入，只是作为读入的数据段，在真正发送的时候再变为发送的数据结构段
4.通过短接B9以及相邻的5V引脚可以方便的开始，并且不用对系统板进行任何的变动，并且可以实现输入的时间随机，在中间第二次输入还改变了一次种子，让输入更随机，由于把系统的始终作为种子，这样的按键之后会实现种子的随机，并且没有复杂的ADC或者DAC结构，并且可以控制输入时间的开始，不会出现匆忙输入，错误输入的情况
5.两个程序一起输出，中间有确认按钮，方便输入，以及写入的一次性。

# 编码程序说明：
编辑编码程序文件夹为/character_changed_executor
在这个文件夹里有我们需要的.exe可执行文件，通过这个程序可以对我们的程序进行编码，编码为USB HID输入形式
输出文件为inputc.txt, 输出文件为outputc.txt, 在输入之前需要删除里面的中文以及其他在键盘上没有的符号,
有中文的话会产生错误

# 编码程序版本说明：
版本1.0.0仅仅只对几个特殊转义字符进行了说明
版本2.0.0是第一次比较完整的详细的列出了各个按键的映射表，通过这些项的映射，第一次能比较好的列出相应的编码
版本2.1.0是在2.0.0的基础上进行大规模功能性的增加，主要是增加了对于映射个数的统计，方便进行数组的扩充的改变
版本2.1.1是调整了接收字符的变量a的类型，由char调整为int类型，使其能支持更广泛的传入

# STM32说明：
STM32Config里面是用STM32CubeMX建立的工程，然后用Keil5进行编程处理的,安装keil5软件，
按照目录点击下面的文件
./STM32Configue/keybord_simulator/MDK-ARM/keybord_simulator.uvprojx
然后找到左侧的Application/User/Core，然后找到main,在最上面的29行到32行是我们要更改的地方
length1和length2是用生成程序自动编写之后生成出来，
下面的两个数组是填写生成之后的编码内容，生成的是文字，在这里拷贝过来之后就可以变成数字看待了，这些就是要发送的二进制编码的十六进制形式，
下面的A是用于随机之后的补位，为了防止随机之后对其取余数后出现零的情况，而且由于执行一个的时间非常短，就会出现缓冲区错误，Win系统会进行输入的整合和自我调整，所以会出现颠倒的情况，所以补充了这个位置的数字，一般其实改大改小也不是很明显，除非非常大会非常慢，并且不建议更改
其他的都不是特别的问题了，两个输入模块的代码除了输入数组和相应的长度以外都是雷同的，都是完成一个，组装一个输出序列，然后进行输出到目标设备中
其中比较重要的就是shift按键，在这个里面只有这一个按键会对其他的按键造成影响，所以，一旦有这个按键出现，就多读一个，把0x02也就是shift按键当作功能按键进行使用，后面紧跟的八个零是清除之前按下的按键的信号的
以上就是比较重要的内容了，感觉这次工程比较的完整，虽然也有增加的功能，txt里面的仅仅只是测试用例
